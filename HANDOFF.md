# Handoff — web-app (HEP Tracking Table)

## What this is

A simple SvelteKit app in `web-app/` that renders the HEP tracking data as an HTML table. The data is a JSON file hosted in this repo and fetched at runtime from GitHub raw.

## What was done

- Scaffolded a minimal SvelteKit project (JavaScript, Svelte 5) into `web-app/` via `npx sv create` (template `minimal`, `--no-types`, `--no-add-ons`).
- Verified the production build works (`npm run build`) and smoke-tested the SSR output (table renders 4 rows, inline `<span>` styles from the data come through).

## Files created / changed

- `web-app/src/lib/store.js` — shared store module:
  - `DATA_URL` — URL of `data/hep-tracking.json` on GitHub raw (the source of truth for the URL).
  - `rows` — Svelte `writable` store, populated from loaded data (available for future shared state).
- `web-app/src/routes/+page.js` — SvelteKit `load({ fetch })` that GETs `DATA_URL`, throws `error(status, msg)` on failure, returns `{ rows }`.
- `web-app/src/routes/+page.svelte` — the page:
  - Renders a `<table>` with columns **Organization, Date, Sector, Explanation**.
  - `Explanation` is rendered with `{@html row.Explanation}` so the inline HTML tags in the data (e.g. `<span style='color:#FF9900'>…</span>`, `font-weight:bold`) are honored.
  - Syncs `rows` store with loaded data in an `$effect`.
  - Vanilla CSS in a `<style>` block (no Tailwind, no libraries).
- `web-app/.gitignore` was regenerated by the scaffold.

## How to run

```bash
cd web-app
npm run dev          # dev server
npm run build        # production build
npm run preview      # preview the build
```

## Data format

`data/hep-tracking.json` — array of objects: `{ Organization, Date, Sector, Explanation }`. `Explanation` contains trusted HTML (inline `<span>` with `style`).

## Notes / decisions

- `{@html}` is intentionally used on `Explanation`; the source is this repo's own data, so it's considered trusted. If untrusted data ever enters the pipeline, sanitize first.
- The `$effect` that calls `rows.set(...)` is intentional (keeps the shared store in sync), not a reactivity anti-pattern.
- `+page.js` `load` fetches server-side (SSR) and the URL allows CORS, so it also works client-side on navigation.
- No sorting/filtering yet; data is rendered in fetch order.
